# 主题驱动的图表规划

图不是流程的装饰，是论证的一部分。**先有问题，再选图型；先有数据，再画图。** 不要用固定四件套（结构图 / 分类图 / PRISMA / 工作量图）套所有主题。

## 三条原则

1. **一图一问**：每张图必须回答一个具体问题，并绑定到 `claim_id` 或段落；
2. **数据先于图**：没有可核验数据就不画；示意图只在解释结构时用，并标明“示意”；
3. **主题决定维度**：推荐系统关心方法族与数据集，医学综述关心人群与结局，教育综述关心样本与干预——维度从 RQ 来，不从模板来。

## 先问统计问题，再画图

不要上来就画。先跑 `scripts/stat-questions.mjs`：它读提取表，按主题给字段打相关性，生成“方法各有多少篇”“方法随年份怎么变”“哪些数据集用得最多”这类候选问题。

- 只保留能支撑论点的 **3–6 条**；
- 每条补 `claim_id` 与结论式标题；
- 文本字段（局限、发现）先编码再统计，不能拿分词当结论。

统计问题回答“多少 / 怎么分布”，不回答“为什么更好”。后者要靠关系表与论证。

## 从问题到图型

| 你想回答 | 候选图型 | 需要的数据 |
|---|---|---|
| 这个方向怎么随时间变 | 折线 / 堆叠面积 / 时间线 | 年份 + 类别 |
| 方法族怎么构成 | 横向条形 / 矩形树图 / 热力矩阵 | 方法族 + 数量 |
| 不同方法在哪些数据集上测过 | 热力矩阵 / 点图 | 方法 × 数据集 |
| 结论之间是什么关系 | 网络图 / 关系矩阵 | 文献对 + 关系类型 |
| 证据强度够不够 | 气泡图（年份 × 质量 × 数量） | 年份 + 质量 + 篇数 |
| 筛选过程是否透明 | PRISMA 流程图 | 各阶段计数 |
| 覆盖是否有缺口 | 覆盖矩阵热力图 | 方向 × 覆盖状态 |

## 按数据形状选

| 数据形状 | 优先 | 避免 |
|---|---|---|
| 类别 ≤7 | 条形 / 点图 | 饼图（难比较） |
| 类别 >7 | 横向条形 / 树图 | 挤在一起的竖条 |
| 时间 ≥5 个点 | 折线 | 每年一根柱子 |
| 二维矩阵 | 热力图 | 多张条形图 |
| 只有计数、没有数值 | 条形 / 堆叠条 | 散点、回归线 |

## 图表计划

写在 `04_综合/图表计划.csv`：

| 字段 | 说明 |
|---|---|
| `figure_id` | Fig1 |
| `question` | 这张图回答什么 |
| `claim_id` | 绑定哪条论断（可空，但要有段落） |
| `chart_type` | bar / hbar / line / stacked_bar / scatter / heatmap |
| `data_file` | 聚合后的 CSV |
| `x` / `y` / `group` | 列名 |
| `title` | 结论句式标题，不写“某某分布图” |
| `note` | 为什么需要这张图 |

先跑 `scripts/fig-plan.mjs` 从数据里生成候选，再按主题增删；不要直接照单全收。

## 反模式

- 固定四件套，不管主题需不需要；
- 为了“显得丰富”加图，正文却不引用；
- 图与表重复同一信息；
- 没有数据却画“趋势图”；
- 标题是标签（“方法分布”）而不是结论（“图方法集中在 2020 年后，知识增强仍是少数”）。

## 与 nature-figure 的分工

| 模块 | 管什么 |
|---|---|
| 本文件 + `fig-plan` | 画什么、为什么画、用什么数据 |
| `nature-figure` | 怎么画得合规、好看、可复现（字体、配色、导出） |
| `fig-render.py` | 把计划里的统计图直接渲染成 PDF/SVG/PNG |

## 门禁

- 每张图都有 `question` 与数据文件；
- 正文有引用（“见图 2”）；
- 图表计划里的图要么已出图，要么明确删掉并说明；
- 不用示意图冒充数据图。
