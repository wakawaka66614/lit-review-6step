# 文献覆盖审计（Literature Coverage Audit）

写作前问一句：**这批文献够不够支撑这篇综述？** 不是数篇数，而是看三个维度有没有塌。

## 三个维度

| 维度 | 审什么 | 典型缺口 |
|---|---|---|
| 主题覆盖 | 核心研究方向是否都在 | 只覆盖图协同过滤，漏掉动态图、多模态、公平性 |
| 方法覆盖 | 重要方法类别是否遗漏 | 只收 GCN 系，漏掉 GAT / 知识图谱 / 序列图 |
| 时间覆盖 | 奠基、发展期、最新是否都有 | 全是 2024–2026，缺奠基工作 |

## 覆盖矩阵

写在 `04_综合/覆盖矩阵.csv`：

| 字段 | 说明 |
|---|---|
| `direction` | 研究方向 |
| `importance` | 核心 / 次要 |
| `classic_count` | 该方向奠基文献数（如 2019 年前） |
| `recent_count` | 近三年文献数 |
| `fulltext_count` | 已全文精读的篇数 |
| `status` | 充分 / 基本充分 / 不足 / 待补充 |
| `note` | 判断依据；缺口写进第 6 章 |

## 状态判定（指导，不是硬公式）

| 状态 | 参考条件 | 处理 |
|---|---|---|
| 充分 | 有经典、有近期、≥3 篇全文 | 可写 |
| 基本充分 | 三项都不为零，但某一项偏少 | 写作时标注局限 |
| 不足 | 缺经典，或全文为 0 | 回 S3/S4 补检索或补读 |
| 待补充 | 0–1 篇 | 不能单独成节；写进未来方向 |

**数量只是下限**：领域成熟度、方向重要性、RQ 的相关性都要写进 `note`。核心方向不能停在“不足”。

## 放在哪

- **S4 结束、S5 开始前**：先填覆盖矩阵，再定提纲；
- 覆盖不足 → 回 S3 补检索（引文追踪优先）或 S4 补全文；
- 核心方向的缺口 → 第 6 章“挑战与未来方向”的原料。

## 与检索阶段的分工

| 阶段 | 回答 |
|---|---|
| S3 检索 | 找到哪些论文 |
| S4 精读 | 每篇讲了什么 |
| **覆盖审计** | **这些论文够不够支撑综述** |
| S5 写作 | 怎么组织成论证 |

## 门禁

- 覆盖矩阵每个核心方向都有 `status` 与依据；
- 核心方向不能为“不足/待补充”；
- 缺口要么补文献，要么明确写进第 6 章；
- 不允许用“文献较多”代替覆盖判断。
