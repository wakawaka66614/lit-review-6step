# 证据与语言规范

三个 skill 共用。写提纲、正文、摘要时都适用。**冲突时以本文为准。**

## 一、四条语言规范

| 规范 | 要求 |
|---|---|
| 默认中文 | 解释、正文、提纲、摘要用中文 |
| 保留英文 | 论文标题、变量名、模型名、软件命令、参考文献条目保持原文，不翻译 |
| 不编造 | 不虚构 DOI、作者、期刊、页码、数据、实验结论 |
| 标注来源 | 定量结论、数据集、图表必须带来源标签 |

## 二、核验等级（五级）

“读过摘要”不等于“核验过全文”。按证据能支持什么来分级：

| 标签 | 含义 | 能支持什么 |
|---|---|---|
| `全文核验` | 读过全文，确认方法、数字、局限 | 具体论断、方法细节、实验数字、局限判断 |
| `摘要核验` | 只读过摘要 | **仅**摘要明确写出的内容；不能支撑方法细节或实验数字 |
| `元数据核验` | 只确认了题录（DOI、作者、出处） | 只能确认论文身份与出版信息，不能支撑学术判断 |
| `未核验` | 没读或拿不准 | 不能形成正式学术断言，只能进 to-verify |
| `用户提供` | 用户给的文献、数据、笔记 | 按用户声明的可靠度使用，仍需标来源 |

写作时每个强论断必须绑定 `claim_id`（见 `lit-review-6step/references/claim-evidence.md`），并在台账里记录 `verification` 等级。

## 三、写作时的四条硬检查

1. **论断可回溯**：每个强论断（“X 能改善 Y”“A 优于 B”）必须能指回台账里的 `claim_id`；没有证据就降级为“待核”。
2. **等级匹配**：`摘要核验` 的行不能用来支持方法细节或实验数字；`元数据核验` 不能支撑任何学术判断。
3. **数字有出处**：样本量、准确率、年份窗、文献数，都要能指到具体文献或检索日志。
4. **不确定就明说**：写“未查到”，不要用“研究表明”“大量文献指出”兜底。

## 四、交付前附 to-verify 清单

每次交付末尾加一段：

```markdown
## 待核
- [ ] 某某结论（只在摘要里见过，未读全文）
- [ ] 某某数字（来源待查）
```

清单不为空时，正文对应位置必须标“待核”。清单为空也要写“无”。

## 五、语言细节

- 不用“随着……的快速发展”“近年来受到广泛关注”开头。
- 不用“众所周知”“显而易见”这类无依据的断言。
- 引用格式全文统一（GB/T 7714 或 APA），不在同一篇里混用。
- 中英混排：英文术语与中文之间留空格；英文术语不硬译（如 transformer 不译“变换器”）。

## 六、适用范围

- `lit-review-6step`：S3 建候选表时打标签，S5/S6 引用前核对。
- `survey-writing`：写正文时逐段检查引用与数字。
- `survey-abstract`：摘要里的每个数字都要能回到正文。
