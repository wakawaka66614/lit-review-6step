# V2.0 重构计划（2026-11-17）

> 来源：用户对仓库的完整评审意见。本文是修改依据，不是讨论稿。
> 总体判断：工程化程度尚可，但仍是“文献综述项目管理流程”，没有解决高质量综述最难的四件事——证据可靠性、脉络综合、分类合理性、论断可验证性。**不推倒重做，调整核心设计。**

## 一、现状诊断

| 模块 | 评价 | 主要问题 |
|---|---|---|
| 工作流设计 | 较好 | 六阶段、产物、入口契约、门禁完整 |
| 检索与筛选 | 需加强 | 通道单薄、筛选协议不严、系统综述支持不足 |
| 深度分析 | 明显不足 | 缺方法学评价、证据强度、跨文献关系、主张级证据管理 |
| 结构设计 | 过于僵化 | 默认“新技术×旧问题”，为结构制造分类 |
| 写作与引用审计 | 有漏洞 | 事实核验/引用核验没有闭环 |
| 工程实现 | 需修复 | 安装覆盖、依赖未锁版本、兼容性不一致 |

## 二、七类问题与修改决定

### P0-1 结构被单一模式绑架

问题：`SKILL.md`、`survey-structure.md`、`commands/survey-outline.md` 把“新技术×旧问题”设为默认；强制 A/B 两套 taxonomy、B 类数=章数、默认 b_i→a_i 配对；与 `survey-writing` 的“一套主维度”自相矛盾。

决定：**取消固定结构，改为结构选择器**。保留模式 A 作为可选之一，新增：技术演进、方法分类、问题导向、跨学科、系统综述、评价比较。分类必须从文献归纳；一篇只用一套主维度。

### P0-2 缺论断—证据映射

问题：证据链是 候选表→提取表→正文，缺“论断 ↔ 证据”中间层；`evidence-norms.md` 把“读过摘要”和“读过全文”都算“已核验”。

决定：
1. 增加 **Claim-Evidence Ledger**（论断—证据台账），字段：Claim ID、论断、Evidence ID、文献 ID、证据位置、证据类型、支持程度、适用条件、核验状态。
2. 核验状态拆四级：**全文核验 / 摘要核验 / 元数据核验 / 未核验**。
3. 正文每个强论断必须绑定 Evidence ID；S6 审计按台账核。

### P0-3 检索与 PRISMA 不够严谨

问题：过度依赖 AMiner（单通道、无引文网络）；未强制引文追踪；硬编码“4 英 2 中”；只存最终候选表，不存原始检索结果；PRISMA 计数把“未获取全文”和“全文排除”混在一起；E7“方法不可比”被当通用排除理由；PRISMA 被无条件强加给所有综述类型。

决定：
1. 检索拆四类来源：综合库、专业库、元数据 API、引文追踪（前向/后向）。
2. 数据库按领域/问题决定，不设数量门槛。
3. 保存原始检索结果（`01_检索/原始检索结果.csv`）。
4. PRISMA 2020 分阶段计数：识别 → 去重 → 题摘筛选 → 全文获取（获取到/未获取）→ 资格评估 → 纳入。
5. E6 拆为“全文不可得（记录，不计入资格排除）”；E7 改为“不符合预设纳入标准”，并注明异质性本身不是排除理由。
6. 按综述类型选择报告规范（PRISMA / PRISMA-ScR / 叙事综述不强制）。

### P0-4 缺研究质量评价

问题：只提取“局限”，不评价可信度；不同质量的证据被同等对待。

决定：增加 **Quality Appraisal** 模块，按研究设计选框架（定量/定性/混合/CS 实验），输出低/中/高与依据，不搞全学科统一评分表。

### P1 其他问题

- 多源检索与引文追踪强制执行；
- 跨文献综合从“两篇对撞”改为“观点→证据→关系→综合→局限”；
- 引用与事实自动审计闭环。

### P2 写作与工程

- 摘要/图表/期刊适配优化；摘要五段保留逻辑功能，不强制句式与比例；“摘要蓝图”与“正式摘要”分阶段。
- 安装脚本默认备份、不删除；依赖锁版本/Commit；真正支持 `.claude`；版本号统一；补 `自检清单.md` 模板；补端到端测试。

## 三、V2.0 架构

```text
S0 研究任务定义：RQ · 综述类型 · 目标期刊 · 范围契约 · 检索协议
S1 多源文献发现：综合库 · 专业库 · 元数据 API · 前向/后向引文 · 迭代检索
S2 筛选与资格判断：去重 · 题摘 · 全文获取 · 资格评估 · PRISMA 统计
S3 深度阅读与质量评价：方法/实验/数据提取 · 局限 · 质量评级
S4 证据综合与知识组织：概念矩阵 · 方法演进 · 冲突 · 证据强度 · 缺口 · 动态分类
S5 结构与写作：结构选择 · 论点规划 · 分章写作 · 图表 · 论断绑定 Evidence ID
S6 多维审计：事实 · 引用 · 逻辑 · 语言 · 格式
迭代：证据不足回 S1；分类不稳回 S4；不强行进写作
```

本质变化：从“选题→检索→筛选→精读→写作→统稿”升级为“研究问题→文献发现→证据构建→知识综合→学术表达→质量验证”。

## 五、对照测试（必须做）

选真实主题 + 人工核验文献集，对比 A 普通 LLM / B 现版 / C V2.0，评价：覆盖率、真实性、证据准确率、提取准确率、分类合理性、综合深度、引用准确率、成本、人工大改比例。

## 六、保留与推翻

保留：六阶段、项目目录与固定产物、主题契约与入口、概念矩阵与冲突地图、结构与语言审查分离。

推翻：单一七章节标准、每段两篇对撞硬要求、文献/数据库数量门槛、摘要核验=全文核验、同模型多角色自检=独立质量保证。

目标定位：**Evidence-Driven Literature Review Agent**，不是“自动填六个文件夹的文档生产 Skill”。
