# 端到端对照测试计划

> 目的：验证这套流程是否真的提升综述质量，而不是只验证文件齐不齐。
> 这份计划本身就是交付物；真实对照需要选定主题与人工核验文献集后执行。

## 一、设计

同一主题、同一截止日期，三条条件并行：

| 条件 | 做法 |
|---|---|
| **A 基线** | 普通 LLM 直接写综述（一次性提示，不给流程） |
| **B 现版** | 当前 lit-review-6step 全流程 |
| **C 改进版** | 完成 P0/P1 改造后的版本（本次之后即 C） |

每条条件记录：模型、提示词、耗时、token 量、人工修改量。

## 二、材料

1. **主题**：选一个有明确边界的真实题目（不要“人工智能综述”这种）。
2. **金标准文献集**：人工检索 + 核验的 20–40 篇核心文献，标 `why_core` 与 `verified_by`。
3. **评价人**：至少 1 名领域内人员；分类合理性建议 2 人盲审。

## 三、指标

| 维度 | 测法 | 目标 |
|---|---|---|
| 文献覆盖率 | 金标准中被引用的比例 | ≥70% |
| 文献真实性 | 抽查 20 条引用，核 DOI/作者/年份 | 100% 可核验 |
| 证据准确率 | 抽 20 条论断回原文 | ≥90% 被支持 |
| 提取准确率 | 抽 10 篇，比方法/数据/结论/局限 | ≥80% 字段正确 |
| 分类合理性 | 专家盲审分类边界与稳定性 | 通过/不通过 |
| 综合深度 | 是否出现 L3+ 关系判断、冲突解释 | 每主题 ≥1 |
| 引用准确率 | 引用与论断对应 | ≥95% |
| 成本 | 时间、token、人工修改分钟 | 记录 |
| 人工大改比例 | 成稿中被大幅改写的段落占比 | 越低越好 |

## 四、流程

```powershell
# 1. 建运行目录与评分表
node scripts/e2e-init.mjs --topic "你的主题" --out e2e

# 2. 填金标准
#    e2e/<slug>-<date>/gold-set.csv

# 3. 三条条件各跑一遍，产物放 runs/A|B|C/
# 4. 机械评分（覆盖率、未知引用、弱证据 claim）
node scripts/e2e-score.mjs --run e2e/<slug>-<date>/runs/C --gold e2e/<slug>-<date>/gold-set.csv --out e2e/<slug>-<date>/scores-C.md

# 5. 人工评分写 scores.csv，结论写 RESULTS.md
```

## 五、诚实边界

- 一次对照不能证明普适优越，只能证明“在这个主题上”；
- 评价人不是独立第三方时，结论只能算内部评估；
- 必须报告失败案例与人工大改比例，不能只报好看的数字。
